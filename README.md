# 対人スタイル診断（Interpersonal Compass）

対人円環の相補性理論（Interpersonal Circumplex）と、ラポール理論
（Tickle-Degnen & Rosenthal, 1990）にもとづく対人スタイル診断アプリです。
ビルド不要・依存ライブラリなしの素の HTML / CSS / JavaScript のみで構成されており、
GitHub Pages にそのまま公開できます。

## 構成

```
personality-quiz/
├── index.html          スタート／質問／計算中／結果の4画面（1ページ内で切り替え）
├── css/
│   └── style.css       深紺×真鍮の計器盤（コンパス）テーマ
├── js/
│   ├── data-questions.js   20問の設問データ（軸ラベルは開発者専用・非表示）
│   ├── data-types.js       16タイプ＋バランス型の結果テキスト・相性データ
│   └── app.js              進行制御・SSM（Structural Summary Method）計算・結果描画・シェア画像書き出し
└── README.md
```

## 実装した仕様・追加要件

- **1画面1問**：質問は20問すべてランダム順で出題し、回答すると自動で次の質問へ遷移。進捗はページ上部のプログレスバーで表示（`前の質問へ` で1問戻れます）。
- **軸の非表示**：「主導権」「素直さ」などの軸ラベルはユーザー画面に一切表示しません（`data-questions.js` 内のコメント参照）。
- **SSM（Structural Summary Method）による判定**：仕様書 4-1 の計算式（8方向の生スコア→コサイン曲線フィッティング→θ0・Amplitude算出）をそのまま実装。Amplitudeが閾値（0.5）未満の場合は「バランス型」として17番目の結果に分類します。`js/app.js` の `computeResult()` を参照。
- **会話エネルギー軸**：4問の平均が2.5未満で「速」、2.5以上で「緩」の二値判定（該当なしを作らない）。
- **文章の強弱システム**：決定軸の偏差（中央値3からの距離）に応じて、結果文の冒頭を「弱め／はっきり／かなり強い」の3段階で出し分け。
- **16タイプ＋バランス型**：内部記号（PA〜NOなど）はコード内部でのみ使用し、ユーザーには固有のタイプ名のみ表示。
- **相性表示**：4-2の相性表にもとづく「最も相性がよいタイプ」と、①②のキャプション原稿をそのまま使用した詳細な相性の説明。
- **結果のシェア画像書き出し**：Canvas でタイプ名・キャッチコピー・コンパス図を描画し、PNG としてダウンロード。
- **注記**：医学的・臨床的診断ではない旨、いつでも再診断できる旨を明記。
- **プライバシー**：診断結果はすべて端末内（ブラウザのメモリ）で計算され、外部には一切送信されません（バックエンド自体が存在しません）。実際のマッチング機能（他モジュール）と接続する場合は、この20問の回答データと算出ロジックを流用してください。
- **UI 参考**：16Personalities を参考に、1問1画面・大きなCTA を採用。回答はスライダーではなく1〜5の丸ボタン（Likertスケール）にしており、中央の「3」も他の選択肢と同じように独立してタップできます。配色はクリーム地にコーラル×ミントの軽やかなトーン。
- **左右ラベルの視認性**：各質問の左端／右端の説明文は、選択肢ボタンの真上に「左寄せ／右寄せ」で並べており、どちらの向きがどちらの意味かをスマホでも直感的に把握できるようにしています。
- **戻る／次への操作**：ヘッダーに「← 前の質問」（左）「X/20」（中央）「次の質問 →」（右）を配置。前の質問に戻って確認したあと、選び直さずそのまま先へ進めます（未回答の質問では「次の質問」は押せません）。
- **結果画面のイラスト差し替え**：`assets/illustrations/<タイプコード>.png` を配置するだけで、結果画面上部のアイコンが自動でそのイラストに切り替わる仕組みにしています（未配置の間はタイプ名の頭文字を丸アイコンで仮表示）。対人円環（コンパス図）は視認性・環境依存の表示崩れの問題があったため削除しました。

## ローカルで確認する

ブラウザのセキュリティ制限により `file://` から直接開くとフォント等が正しく読み込めない場合があるため、簡易サーバーを推奨します。

```bash
cd personality-quiz
python3 -m http.server 8000
# → http://localhost:8000 にアクセス
```

## GitHub Pages への公開手順

1. このフォルダの中身をリポジトリのルート（または `/docs` フォルダ）にそのまま push します。
2. GitHub リポジトリの **Settings → Pages** を開きます。
3. **Source** で対象ブランチ（例: `main`）とフォルダ（`/root` または `/docs`）を選択し、**Save**。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

ビルドステップは不要です（静的ファイルのみ）。

## 今後の拡張余地（仕様書に記載のスコープ外の部分）

- 章5の「相性判定ロジック（連続値ベースの重み付きスコア）」は、実際のマッチング一覧（他ユーザーとの比較）が前提の機能のため、本診断単体アプリには含めていません。診断結果（Agency・Communion・会話エネルギーの3つの生スコア）は `computeResult()` の戻り値から取得できるので、マッチング機能側にそのまま引き渡せます。
- Amplitude閾値（暫定0.5）や強弱の境界値（0.8 / 1.5）は仕様書に基づく暫定値です。実測データが揃い次第、`js/app.js` の該当箇所を調整してください。
